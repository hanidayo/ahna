# 직접 빌드해서 배포하기

이 저장소를 내 GitHub 계정으로 복사해서, GitHub Actions로 모든 설치 파일(Windows·Mac·iPhone·Android·서버)을 만들 수 있습니다. 내 컴퓨터에 개발 도구를 설치할 필요가 없습니다.

내가 만든 설치 파일은 **내 저장소의 Releases**를 보고 새 버전을 확인합니다. 그래서 내 저장소에 새 버전을 올리면, 그 파일을 설치한 사람들 앱에 업데이트 알림이 갑니다.

## 1. 저장소 준비

1. GitHub에서 이 저장소를 **Fork**하거나, 소스를 받아 새 저장소에 올립니다.
2. 내 저장소 › **Settings › Actions › General**
   - Actions permissions: **Allow all actions**
   - Workflow permissions: **Read and write permissions**

## 2. (권장) 안드로이드 서명 키 등록

안드로이드는 같은 키로 서명해야 새 버전이 기존 앱 위에 설치됩니다. 키를 등록하지 않으면 빌드할 때마다 임시 키를 써서, 업데이트할 때마다 앱을 지우고 다시 설치해야 합니다.

Java(JDK)가 있는 컴퓨터에서 한 번만 만듭니다.

```bash
keytool -genkeypair -keystore ahna.keystore -storetype PKCS12 -alias ahna -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Ahna"
# 비밀번호를 두 번 묻습니다. 잊지 않게 적어 두세요.
base64 -w0 ahna.keystore > ahna.keystore.txt      # Mac은: base64 -i ahna.keystore -o ahna.keystore.txt
```

Windows PowerShell이라면: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("ahna.keystore")) > ahna.keystore.txt`

내 저장소 › **Settings › Secrets and variables › Actions › New repository secret**

| 이름 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `ahna.keystore.txt`의 내용 전체 |
| `ANDROID_KEY_PASSWORD` | 위에서 정한 비밀번호 |

`ahna.keystore` 파일은 안전한 곳에 보관하세요. 잃어버리면 이후 버전을 기존 앱 위에 설치할 수 없습니다.

(선택) `APPLE_TEAM_ID`: 아이폰 앱을 서명할 Apple 팀 ID(10자리). 몰라도 됩니다.

## 3. 빌드하기

내 저장소 › **Actions › release › Run workflow**

| 입력 | 값 |
|---|---|
| version | `1.0` 처럼 X.Y |
| publish | `true`: Releases에 게시 / `false`: 빌드가 되는지만 확인 |

20~40분쯤 걸립니다(Mac·iPhone 빌드가 가장 오래 걸리고, GitHub의 Mac 빌드 서버가 붐비면 더 기다릴 수 있습니다). 끝나면 **Releases**에 `v1.0`이 생기고 아래 파일이 올라갑니다.

| 파일 | 내용 |
|---|---|
| `Ahna-Setup.exe`, `Ahna-Windows.zip` | Windows 앱 |
| `Ahna-Mac.zip` | Mac 앱 |
| `Ahna-iOS.ipa` | iPhone · iPad 앱(서명 전) |
| `Ahna-Android.apk` | Android 앱 |
| `Ahna-Server.zip` | 서버 |
| `latest.json` | 앱들이 새 버전을 확인하는 파일 |

새 버전을 낼 때는 버전 숫자만 올려서(`1.1` 등) 다시 실행하면 됩니다. 같은 버전으로 다시 실행하면 그 버전의 릴리스를 새로 만듭니다.

## 앱을 고쳤을 때 알아 둘 것

- **버전**: `scripts/set_version.py`가 모든 플랫폼의 버전을 한 번에 맞춥니다(빌드할 때 자동 실행).
- **업데이트 저장소**: `scripts/set_repo.py`가 빌드한 저장소 이름을 앱에 넣습니다(자동 실행). 그대로 둔 소스로 직접 빌드하면 업데이트 확인을 하지 않습니다.
- `windows/Ahna/TransferServer.cs`와 `src/TransferServer.cs`, `windows/Ahna/DirectChannel.cs`와 `src/DirectChannel.cs`, `ios/Shared/DirectLink.swift`와 `mac/Sources/DirectLink.swift`는 같은 파일이어야 합니다.
- 서버만 고쳤다면 Releases의 `Ahna-Server.zip`만 새로 받아 서버를 업데이트하면 됩니다.

## 사용하는 포트

| 포트 | 쓰는 곳 |
|---|---|
| 443 (바깥) | 서버 HTTPS (Caddy 또는 NAS 역방향 프록시) |
| 45833 (서버 안) | 아나 서버 프로그램 (127.0.0.1에서만) |
| 45861 (각 기기 안) | 앱 내부 서버 (127.0.0.1에서만) |
| 45863 (같은 Wi-Fi) | 같은 Wi-Fi 바로 보내기 (암호화) |
