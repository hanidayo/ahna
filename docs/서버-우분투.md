# 아나 서버 만들기 — 우분투(리눅스)

집이나 사무실의 리눅스 컴퓨터에 아나 서버를 띄우는 방법입니다. 우분투 22.04 / 24.04 기준이고, 다른 리눅스도 Docker만 되면 거의 같습니다.

다 하고 나면 이렇게 됩니다.

```
바깥 기기 ──HTTPS(443)──▶ 공유기 ──▶ 이 컴퓨터: Caddy(인증서 자동) ──▶ 아나 서버(127.0.0.1:45833)
```

## 준비물

| 준비물 | 설명 |
|---|---|
| 리눅스 컴퓨터 | 항상 켜 둘 컴퓨터. 미니 PC나 안 쓰는 노트북이면 충분합니다(메모리 1GB 이상) |
| 공유기 관리 권한 | 포트포워딩(바깥 → 이 컴퓨터) 설정이 필요합니다 |
| 주소(도메인) | `ahna.내도메인.com` 같은 주소. 도메인이 없으면 무료 [DuckDNS](https://www.duckdns.org)를 쓰면 됩니다 |

> 서버 프로그램은 파일을 저장하지 않고 흘려보내기만 하므로 저장 공간은 거의 필요 없습니다. 서버를 거칠 때의 속도는 **집 인터넷 업로드 속도**를 넘지 못합니다.

---

## 1. Docker 설치

터미널(또는 SSH)에서:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

한 번 로그아웃했다가 다시 로그인한 뒤 `docker version`이 오류 없이 나오면 됩니다.

## 2. 서버 파일 받기

이 저장소의 **Releases**에서 `Ahna-Server.zip`을 받습니다.

```bash
sudo apt install -y unzip
mkdir -p ~/servers && cd ~/servers
# 아래 주소의 '저장소'는 설치 파일을 받은 GitHub 저장소(소유자/이름)로 바꾸세요.
wget -O Ahna-Server.zip https://github.com/저장소/releases/latest/download/Ahna-Server.zip
unzip Ahna-Server.zip && cd ahna-server
```

## 3. 주소(도메인) 정하기

앱에 넣을 서버 주소를 정합니다. 아래 둘 중 하나를 고르세요.

### 가. 내 도메인이 있을 때 (예: Cloudflare에서 산 도메인)

1. 도메인 관리 화면에서 `ahna` 같은 이름으로 **A 레코드**를 만들고, 값에 **집 공인 IP**를 넣습니다.
   - 집 공인 IP는 공유기 관리 화면의 "외부 IP"나 <https://ifconfig.me> 에서 볼 수 있습니다.
2. **Cloudflare를 쓰면 반드시 회색 구름(DNS only)**으로 두세요. 주황 구름(프록시)을 켜면 큰 파일이 막히고, 국내에서는 해외를 돌아 매우 느려집니다.
3. 가정용 인터넷은 공인 IP가 가끔 바뀝니다. 바뀌면 자동으로 고쳐 주는 DDNS를 함께 띄우세요(아래 4단계의 "Cloudflare DDNS").

### 나. 도메인이 없을 때 (무료 DuckDNS)

1. <https://www.duckdns.org> 에 로그인하고 원하는 이름을 만듭니다. 예: `myahna` → 주소 `myahna.duckdns.org`
2. 화면 위쪽의 **token** 값을 메모합니다.
3. 공인 IP 자동 갱신은 4단계의 "DuckDNS"를 함께 띄우면 됩니다.

## 4. 설정 파일(.env) 채우기

```bash
cp .env.example .env
openssl rand -hex 32      # 나온 64자리를 AHNA_KEY에 붙여 넣습니다
nano .env
```

| 항목 | 넣을 값 |
|---|---|
| `AHNA_ORIGIN` | 3단계의 주소. 예: `https://ahna.내도메인.com` 또는 `https://myahna.duckdns.org` |
| `AHNA_KEY` | 위에서 만든 64자리 |
| `AHNA_INVITE` | 초대 코드(6자 이상). 함께 쓸 사람에게만 알려 주세요 |
| `AHNA_ADMIN_PASSWORD` | 관리자 페이지 비밀번호(8자 이상). 비워 두면 관리자 페이지가 꺼집니다 |
| `AHNA_DOWNLOADS` | (선택) 설치 파일 주소. 예: `https://github.com/저장소/releases/latest` |

저장: `Ctrl+O` → `Enter` → `Ctrl+X`

**공인 IP 자동 갱신(DDNS)** — 3단계에서 고른 쪽만 `compose.ddns.yaml`로 만들어 둡니다.

<details><summary>Cloudflare DDNS (내 도메인이 Cloudflare에 있을 때)</summary>

1. Cloudflare › My Profile › API Tokens › Create Token › **Edit zone DNS** 템플릿 → Zone Resources에 내 도메인 → 만들기 → 토큰 복사
2. 아래를 실행합니다(`ahna.내도메인.com`과 토큰을 바꿔서).

```bash
echo 'CLOUDFLARE_API_TOKEN=여기에토큰' >> .env
cat > compose.ddns.yaml <<'EOF'
services:
  ddns:
    image: favonia/cloudflare-ddns:1
    container_name: ahna-ddns
    restart: unless-stopped
    network_mode: host
    read_only: true
    cap_drop: [ALL]
    security_opt: [no-new-privileges:true]
    environment:
      CLOUDFLARE_API_TOKEN: ${CLOUDFLARE_API_TOKEN}
      DOMAINS: ahna.내도메인.com
      PROXIED: "false"
      IP6_PROVIDER: none
EOF
```
</details>

<details><summary>DuckDNS (무료 주소를 쓸 때)</summary>

```bash
echo 'DUCKDNS_TOKEN=여기에토큰' >> .env
cat > compose.ddns.yaml <<'EOF'
services:
  ddns:
    image: lscr.io/linuxserver/duckdns:latest
    container_name: ahna-ddns
    restart: unless-stopped
    environment:
      SUBDOMAINS: myahna
      TOKEN: ${DUCKDNS_TOKEN}
      TZ: Asia/Seoul
EOF
```
</details>

`chmod 600 .env` 로 다른 사용자가 못 읽게 해 두세요.

## 5. 공유기에서 포트 열기

1. **이 컴퓨터의 내부 IP 고정**: 공유기 관리 화면의 DHCP 설정에서 이 컴퓨터(`hostname -I`의 첫 번째 `192.168.x.x`)를 고정 할당으로 등록합니다.
2. **포트포워딩**: 외부 **TCP 443 → 이 컴퓨터 443**, 외부 **TCP 80 → 이 컴퓨터 80**을 추가합니다. 80은 인증서를 받을 때만 쓰입니다.
   - ipTIME: 고급 설정 › NAT/라우터 관리 › 포트포워드 설정
3. **이중 공유기 확인**: 공유기 화면의 외부 IP가 <https://ifconfig.me> 값과 다르면(예: `192.168.`·`10.`으로 시작) 공유기가 두 대인 구조입니다. 바깥쪽 공유기(통신사 모뎀)에도 같은 포트포워딩이 필요합니다.

## 6. 서버 켜기

```bash
cp Caddyfile.example Caddyfile
nano Caddyfile          # ahna.example.com 을 내 주소로 바꾸기 (https:// 없이)
docker compose -f compose.yaml -f compose.caddy.yaml -f compose.ddns.yaml up -d --build
```

> DDNS를 쓰지 않으면 `-f compose.ddns.yaml`은 빼세요. 처음에는 서버 프로그램을 빌드하느라 몇 분 걸립니다.

1~2분 뒤 인증서를 받았는지 확인합니다.

```bash
docker logs ahna-caddy 2>&1 | grep -i "certificate obtained"
```

## 7. 확인

- 휴대폰 데이터(LTE)로 `https://내주소/_ahna/health` 를 열면 `{"status":"ok", …}` 가 나와야 합니다.
- **내려받기 화면**: `https://내주소/download` (짧게 `/d`). 서버 주소와 처음 쓰는 방법이 나옵니다. 함께 쓸 사람에게 이 주소와 초대 코드를 알려 주세요.
- **관리자 페이지**: `https://내주소/admin` (`AHNA_ADMIN_PASSWORD`를 넣었을 때)
  - 연결한 기기 목록(이름·종류·온라인 여부·마지막 접속·IP)과 오늘·7일·30일 사용량
  - 기기별 알림 보내기 · 초기화(초대 코드 다시 입력) · 차단 · 목록에서 숨기기, 모든 기기 초기화
  - 전체 공지(앱에 알림으로 뜸), 하루 사용량 한도(넘으면 알림, 원하면 그날 서버 전송 막기)
  - 비밀번호를 5번 틀리면 15분 동안 잠깁니다.

## 자주 쓰는 명령

이 폴더(`~/servers/ahna-server`)에서 실행합니다. 아래에서 `C`는 이렇게 줄여 쓴 것입니다.

```bash
C="docker compose -f compose.yaml -f compose.caddy.yaml -f compose.ddns.yaml"
```

| 할 일 | 명령 |
|---|---|
| 상태 보기 | `$C ps` |
| 서버 기록 보기 | `docker logs ahna-relay --tail 50` |
| 다시 시작 | `$C restart` |
| 끄기 | `$C down` (데이터는 남음) |
| 초대 코드·비밀번호 바꾸기 | `.env` 수정 후 `$C up -d` |

**서버 업데이트**: 새 `Ahna-Server.zip`을 받아 이 폴더에 덮어 풀고(`.env`, `Caddyfile`, `compose.ddns.yaml`은 그대로 두세요) `$C up -d --build`.

**백업**: 관리자 데이터(기기 목록·사용량·공지)는 `admin.json` 하나입니다.

```bash
docker cp ahna-relay:/data/admin.json ./admin-backup.json
```

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 인증서를 못 받음(`docker logs ahna-caddy`에 오류) | 주소가 집 공인 IP를 가리키는지(`nslookup 내주소`), 공유기 443·80 포트포워딩, Cloudflare라면 회색 구름인지 |
| 바깥에서는 되는데 집 안에서 주소가 안 열림 | 공유기가 "NAT 루프백(헤어핀)"을 지원하지 않는 경우입니다. 집 안에서는 같은 Wi-Fi 직접 전송이 쓰이므로 앱은 대부분 문제없습니다 |
| 앱에서 "초대 코드가 설정되지 않았습니다" | `.env`의 `AHNA_INVITE`가 비어 있습니다 |
| 앱에서 "초대 코드를 너무 많이 시도했습니다" | 10분 뒤 다시 시도하세요(같은 IP에서 10분에 10번까지) |
| 서버를 거치는 전송이 느림 | 집 인터넷 업로드 속도가 한계입니다. 같은 Wi-Fi끼리는 서버를 거치지 않습니다 |

### 공유기 포트를 열 수 없을 때

회사·기숙사처럼 포트포워딩이 안 되는 곳이라면 두 가지 방법이 있습니다.

- **클라우드 서버에 올리기**: AWS Lightsail(서울), Vultr(서울) 같은 월 5달러 안팎의 작은 리눅스 서버에 같은 방법으로 설치합니다. 공유기 설정 없이 6단계부터 하면 되고, 3단계의 주소는 그 서버의 고정 IP를 가리키게 합니다.
- **Cloudflare Tunnel**: 포트를 열지 않고 쓸 수 있지만, 국내에서는 해외를 돌아 요청마다 몇 초씩 걸리는 경우가 많고 한 번에 100MB까지만 올라갑니다(앱이 자동으로 나눠 보내긴 합니다). 이때는 Caddy 없이 터널의 서비스 주소를 `http://127.0.0.1:45833`으로 지정합니다.
