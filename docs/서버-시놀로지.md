# 아나 서버 만들기 — 시놀로지 NAS

시놀로지 NAS의 **Container Manager**로 아나 서버를 띄우는 방법입니다. DSM 7.2 이상 기준입니다.

다 하고 나면 이렇게 됩니다.

```
바깥 기기 ──HTTPS(443)──▶ 공유기 ──▶ NAS 역방향 프록시(인증서) ──▶ 아나 서버(localhost:45833)
```

## 준비물

| 준비물 | 설명 |
|---|---|
| Container Manager가 되는 NAS | 패키지 센터에 **Container Manager**가 보이면 됩니다(대부분의 Plus·x86 모델) |
| 공유기 관리 권한 | 포트포워딩(바깥 → NAS) 설정이 필요합니다 |
| 주소 | 시놀로지 무료 주소 `이름.synology.me`를 쓰면 됩니다(아래 2단계) |

> 서버 프로그램은 파일을 저장하지 않고 흘려보내기만 해서 저장 공간은 거의 쓰지 않습니다. 서버를 거칠 때의 속도는 **집 인터넷 업로드 속도**를 넘지 못합니다.
> QuickConnect 주소(`quickconnect.to`)는 쓸 수 없습니다.

---

## 1. Container Manager 설치

**패키지 센터** › `Container Manager` 검색 › **설치**

## 2. 주소 만들기 (DDNS)

1. **제어판 › 외부 액세스 › DDNS › 추가**
2. 서비스 공급자: **Synology**, 호스트 이름: 원하는 이름(예: `myahna`) → 주소 `myahna.synology.me`
3. **"Let's Encrypt에서 인증서 받기 및 기본 인증서로 설정"**에 체크(보이면) → **확인**

이미 쓰고 있는 `이름.synology.me` 주소가 있으면 그대로 써도 됩니다.

## 3. 공유기에서 포트 열기

1. **NAS 내부 IP 고정**: 공유기 DHCP 설정에서 NAS(제어판 › 네트워크 › 네트워크 인터페이스의 IP)를 고정 할당으로 등록합니다.
2. **포트포워딩**: 외부 **TCP 443 → NAS 443**, 외부 **TCP 80 → NAS 80**. 80은 Let's Encrypt 인증서를 받거나 갱신할 때 쓰입니다.
   - ipTIME: 고급 설정 › NAT/라우터 관리 › 포트포워드 설정
3. 공유기 화면의 외부 IP가 <https://ifconfig.me> 값과 다르면 공유기가 두 대인 구조입니다. 바깥쪽 공유기(통신사 모뎀)에도 같은 포트포워딩이 필요합니다.

## 4. 인증서 확인

**제어판 › 보안 › 인증서**에 `이름.synology.me` 인증서가 있으면 됩니다. 없으면:

**추가 › 새 인증서 추가 › Let's Encrypt에서 인증서 얻기** → 도메인 이름 `myahna.synology.me`, 이메일 입력 → **완료**

## 5. 서버 파일 올리기

1. 이 저장소의 **Releases**에서 `Ahna-Server.zip`을 PC로 받습니다.
2. **File Station**에서 `docker` 공유 폴더 안에 `ahna` 폴더를 만듭니다(`docker` 폴더는 Container Manager를 설치하면 생깁니다).
3. 압축 파일을 `docker/ahna`에 올린 뒤, 오른쪽 클릭 › **압축 풀기 › 여기에 압축 풀기**
4. 그러면 `docker/ahna/ahna-server` 안에 `compose.yaml`, `.env.example` 등이 생깁니다.

## 6. 설정 파일(.env) 만들기

NAS에서는 점(.)으로 시작하는 파일을 만들기 번거로워서, PC에서 만들어 올리는 게 편합니다.

1. PC의 메모장을 열고 아래를 붙여 넣은 뒤 값을 바꿉니다.

```
AHNA_ORIGIN=https://myahna.synology.me
AHNA_KEY=여기에64자리
AHNA_INVITE=초대코드
AHNA_ADMIN_PASSWORD=관리자비밀번호
AHNA_DOWNLOADS=
TZ=Asia/Seoul
```

| 항목 | 넣을 값 |
|---|---|
| `AHNA_ORIGIN` | 2단계의 주소. 앞에 `https://`, 끝에 `/` 없이 |
| `AHNA_KEY` | 64자리 임의 16진수(0-9, a-f). <https://www.random.org/cgi-bin/randbyte?nbytes=32&format=h> 에서 나온 값의 띄어쓰기를 지워 쓰거나, 아무 리눅스·맥 터미널에서 `openssl rand -hex 32` |
| `AHNA_INVITE` | 초대 코드(6자 이상). 함께 쓸 사람에게만 알려 주세요 |
| `AHNA_ADMIN_PASSWORD` | 관리자 페이지 비밀번호(8자 이상). 비워 두면 관리자 페이지가 꺼집니다 |
| `AHNA_DOWNLOADS` | (선택) 설치 파일 주소. 예: `https://github.com/저장소/releases/latest` |

2. **다른 이름으로 저장** › 파일 형식 **모든 파일(\*.\*)** › 파일 이름 **`.env`** (앞의 점 포함, 인코딩 UTF-8)
3. File Station으로 `docker/ahna/ahna-server` 폴더에 올립니다.

## 7. 컨테이너 만들기

1. **Container Manager › 프로젝트 › 생성**
2. 프로젝트 이름: `ahna`
3. 경로: **`docker/ahna/ahna-server`** 선택
4. 원본: **"기존 docker-compose.yml 사용"**(`compose.yaml`이 자동으로 잡힙니다)
5. 웹 포털 설정은 건너뛰고 **완료** → 처음에는 서버 프로그램을 빌드하느라 몇 분 걸립니다.
6. 컨테이너 목록에 `ahna-relay`가 **실행 중**이면 됩니다.

## 8. 역방향 프록시 연결

1. **제어판 › 로그인 포털 › 고급 › 역방향 프록시 › 생성**
2. 일반
   - 이름: `ahna`
   - 소스: 프로토콜 **HTTPS**, 호스트 이름 **`myahna.synology.me`**, 포트 **443**
   - 대상: 프로토콜 **HTTP**, 호스트 이름 **`localhost`**, 포트 **45833**
3. **사용자 지정 머리글** 탭 › **생성 › WebSocket** (두 줄이 자동으로 추가됩니다)
4. **고급 설정** 탭 › 프록시 연결 시간 제한·프록시 보내기/읽기 시간 제한을 각각 **3600**초로 늘립니다(큰 파일용).
5. **저장**
6. **제어판 › 보안 › 인증서 › 설정**에서 `myahna.synology.me`(역방향 프록시 항목)에 4단계 인증서가 지정됐는지 확인합니다.

> 같은 주소·443 포트를 이미 다른 역방향 프록시가 쓰고 있다면, DDNS를 하나 더 만들어(예: `myahna2.synology.me`) 그 주소로 연결하세요.

## 9. 확인

- 휴대폰 데이터(LTE)로 `https://myahna.synology.me/_ahna/health` 를 열면 `{"status":"ok", …}` 가 나와야 합니다.
- **내려받기 화면**: `https://myahna.synology.me/download` (짧게 `/d`). 서버 주소와 처음 쓰는 방법이 나옵니다. 함께 쓸 사람에게 이 주소와 초대 코드를 알려 주세요.
- **관리자 페이지**: `https://myahna.synology.me/admin`
  - 연결한 기기 목록과 오늘·7일·30일 사용량, 기기별 알림·초기화·차단·숨기기
  - 전체 공지(앱에 알림으로 뜸), 하루 사용량 한도
  - 비밀번호를 5번 틀리면 15분 동안 잠깁니다.

이제 앱을 설치하고 서버 주소와 초대 코드를 넣으면 됩니다 → [앱-설치.md](앱-설치.md)

## 운영

| 할 일 | 방법 |
|---|---|
| 초대 코드·비밀번호 바꾸기 | `.env`를 고쳐 다시 올린 뒤 Container Manager › 프로젝트 › `ahna` › **작업 › 중지** 후 **빌드**(또는 시작) |
| 서버 기록 보기 | Container Manager › 컨테이너 › `ahna-relay` › **로그** |
| 서버 업데이트 | 새 `Ahna-Server.zip`을 같은 폴더에 덮어 풀고(`.env`는 그대로) 프로젝트 › **작업 › 빌드** |
| 백업 | 관리자 데이터(기기 목록·사용량·공지)는 컨테이너 안의 `/data/admin.json` 하나입니다. Hyper Backup으로 Docker 볼륨을 포함하거나, SSH에서 `sudo docker cp ahna-relay:/data/admin.json /volume1/docker/ahna/` |

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 바깥에서 주소가 안 열림 | 공유기 443 포트포워딩, 역방향 프록시의 소스 호스트 이름이 주소와 똑같은지 |
| 인증서 오류 | 제어판 › 보안 › 인증서에서 역방향 프록시 항목에 맞는 인증서가 지정됐는지, 80 포트포워딩(갱신용) |
| 앱이 연결됐다 끊겼다 함 | 역방향 프록시의 **WebSocket** 머리글을 빠뜨렸는지 |
| 큰 파일이 중간에 실패 | 역방향 프록시 시간 제한(8단계 4번) |
| "초대 코드가 설정되지 않았습니다" | `.env`의 `AHNA_INVITE`가 비어 있거나 `.env` 파일 이름이 틀렸습니다(`.env.txt`가 아닌지 확인) |
| 프로젝트 빌드 실패 | `.env`의 `AHNA_ORIGIN`이 `https://`로 시작하는지, `AHNA_KEY`가 64자리인지 |
